# Architecture rules
- Keep legal pages public and localized through shared legal copy; mount external video engines only after session-scoped explicit permission and unmount them on withdrawal to prevent pre-consent provider requests.
- Derive descending flat-spelled fingerings from the ascending pitch/valve registry so enharmonic notation cannot change playback or grips.
- Keep app welcome delivery in the authenticated contact-sync function with a service-only unique user/email ledger and atomic stage claims; stop ambiguous provider outcomes and unsent legacy offers for reconciliation to prevent duplicate vouchers, mismatched discount emails or mail, and isolate the singleton admin test from production identities.
- Request login and recovery emails through the managed auth client, never the legacy SMTP relay or privileged link generator; keep verification URLs intact and return callbacks to public auth pages.
- Derive membership lookup identity from a verified server-side session; payment imports require a database-backed admin role, and purchase notifications must authenticate before persistence or fulfillment.
- Verify original Digistore24 parameters with the official case-sensitive SHA-512 signature, strip credential fields before storage, keep order ownership immutable and recompute plans from active entitlements while preserving manual overrides.
- Use provider transaction identity for purchase persistence and signature-independent event deduplication; claim purchase welcome mail once per order with a service-only ledger and a single provider attempt, stopping uncertain sends to prevent duplicate replay mails.
- Keep level browsing in the LevelsPage flow, with a reusable LevelGrid for overview tiles; selecting a tile reuses existing video playback and usage checks.
- Serve the branded share image as a static public asset referenced by absolute URLs in the sitewide head so non-JavaScript social crawlers can load it.
- Resolve purchase destinations through the shared verified product-and-payment-plan registry; require exactly one numeric plan query and fail closed without fallbacks so billing choices cannot silently change.
- Keep password recovery public and exempt from mobile app redirects; preserve recovery intent before the auth client consumes callback tokens.
- Use Happy DOM for component tests to avoid native canvas requirements in the managed test sandbox.
- Keep operational mail templates and sync logs admin-only; audio metadata and review prompts require sign-in, and private course PDFs require exact document-to-object binding plus server-side plan entitlement.
- Share PLAN_INFO, calculated discounts and localized PlanTerms across pricing surfaces; the landing page reuses PricingTable to avoid divergent offers.
- Keep IPN event transitions in the shared tested event module; authenticate connection tests before returning exact OK without writes, and never acknowledge persistence failures as successes.- Send the welcome-voucher follow-up from the same contact-sync function, triggered hourly by a scheduler that mints single-use database tokens; claim rows atomically, re-check the voucher at Digistore24 before sending, and never auto-retry uncertain sends, so no long-lived credential exists and no duplicate reminder is possible.
- Drive homescreen icons, lock badges and module guards from the single app registry; locked modules show the homescreen with a login sheet for guests instead of redirecting, so access rules cannot diverge.
- Use the shared homescreen wall and light semantic tokens for every app module; scope legacy contrast adapters to module chrome while retaining image-overlay and gameplay colors and the separate admin theme. Keep practice-tool translations in a shared locale dictionary consumed through the active language hook.

- Serve homescreen shop items only from the cached shop table refreshed at most hourly by a public server function; provider sync publishes new active products automatically, leaves inactive products hidden, and preserves existing admin-curated price, cover, order and visibility fields. Each mounted shop surface reloads after sync and requests hourly refresh so carousel and cards do not require manual approval or page reloads.
- Import original shop covers into the app asset store and cache verified provider prices; subscription cards reuse PLAN_INFO terms and the verified checkout registry so introductory prices never hide recurring charges or select another payment plan.
- Open the shared product purchase dialog from shop cards and carousel before external checkout; reuse PLAN_INFO, PlanTerms and the verified checkout registry for billing selection so compact previews cannot bypass complete purchase terms.
- Host the supplied rhythm workshop as an isolated same-origin static page with its original notation, sampler and microphone engines; a source-validated iframe bridge shares locale and semantic theme tokens, and binary media uses app asset pointers. Beginner lessons remain admin-managed authenticated content.
- Resolve beginner showcases through the shared locale registry and a showcase/video membership table so globally unique Vimeo videos retain existing level ownership; admin-only sync stores provider manual order, and the shared Level player supports inline playback with unchanged usage gates.
- Lazy-load the imported beginner feedback engine only in its authenticated tab, mount one exercise at a time, share Rhythmus Leland glyphs, preserve browser-local progress and stop pending microphone starts on teardown so audio resources cannot survive navigation.
- Share the original same-origin Happybeginners trumpet sprite and valve renderer across feedback and fingering tools; await audio unlock, reject failed loading and allow retry, and cancel pending playback on teardown so silent loading failures cannot masquerade as ready audio.
- Share tuner controls between the inline module page and contextual popups so notation, pitch mapping, microphone detection and Safari unlock behavior stay consistent; use VexFlow and the tested concert-to-written pitch mapping.
- Keep PDF rendering in the shared PdfViewer with the existing local PDF.js worker and authenticated Blob access; use react-zoom-pan-pinch for gestures, normalized per-page strokes in the existing user annotation store, and print only one composite current-page image so zoom cannot move marks or expand print scope.
